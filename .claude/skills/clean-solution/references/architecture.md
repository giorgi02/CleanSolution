## 1. Solution layout

Project names are layer names, **not** prefixed with the solution name (`Core.Domain`, not `InventoryHub.Core.Domain`); only the
`.slnx` file carries the solution name. Namespaces equal folder paths.


## 3. Where does it go?

| Thing | Location |
|---|---|
| Business rule that only needs the entity's own data | method on the entity (`employee.SetLanguages(...)`) |
| Rule that needs other data or services | the use case `Handler` |
| Input shape/format rules | the use case `Validator` |
| "Does X exist?" check needed for a write | handler: `await repo.ReadAsync(id, ct) ?? throw new EntityNotFoundException(...)` |
| Query/filter logic | repository method (`FilterAsync`, `SearchAsync`) - never `IQueryable` leaking out of Persistence |
| Mapping entity → DTO | `.Adapt<TDto>()` in the handler; explicit rules in `Commons/MapperConfig.cs` |
| Interface of anything external (DB, broker, storage, HTTP API, clock, user) | `Core.Application/Interfaces/...` |
| Implementation of that interface | the matching Infrastructure project (or the host, for `IActiveUserService`) |
| Generic helper with no business meaning | `Core.Shared/Extensions` or `Core.Shared/Helpers` |
| HTTP concern (status code, route, header, IFormFile, caching attribute) | Presentation.WebApi |
| Cross-cutting HTTP behavior (logging, validation, exceptions, correlation) | filter or middleware in `Presentation.WebApi/Extensions` - not in controllers |
| Current time | inject `TimeProvider` (registered by `AddApplicationLayer`), never `DateTime.Now` in testable logic |
| Current user | inject `IActiveUserService` |

## 4. Naming conventions

| Kind | Pattern | Example |
|---|---|---|
| Command (changes state) | `{Verb}{Entity}Command` | `CreateEmployeeCommand`, `UpdateEmployeeCommand`, `DeleteEmployeeCommand` |
| Query (reads) | `Get{Entity}Query` / `Get{Entities}Query` | `GetEmployeeQuery`, `GetEmployeesQuery`, `GetMaxMinBySalaryQuery` |
| Notification (background handler) | `{Action}Notification` | `UpsertPositionNotification`, `CheckoutProcessNotification` |
| Output DTO | `Get{Entity}Dto` | `GetEmployeeDto` |
| Reusable input DTO | `Set{Entity}Dto` | `SetEmployeeDto` |
| Repository | `I{Entity}Repository` / `{Entity}Repository` | `IEmployeeRepository` |
| Service port / adapter | `I{Name}Service(s)` / `{Name}Service(s)` | `IDocumentService`, `IHrPortalServices` |
| EF configuration | `{Entity}Configuration` | `EmployeeConfiguration` |
| Seed | `{Entity}Seed` with static `Seeding` array | `PositionSeed.Seeding` |
| Controller | plural entity + `Controller` | `EmployeesController` |
| Route names | `Get{Entities}`, `Get{Entity}ById`, `Add{Entity}`, `Update{Entity}`, `Delete{Entity}` | `Name = "GetEmployeeById"` |
| Kafka topic | snake_case event name, `const string Topic` | `employee_created`, `position_upsert` |
| Kafka consumer | `{Action}Consumer` | `UpsertPositionConsumer` |
| Background worker (in-process queue) | `{Purpose}Worker` | `CheckoutProcessWorker` |
| Layer registration | `Add{Layer}Layer(this IServiceCollection, IConfiguration)` | `AddPersistenceLayer` |

Repository method vocabulary: `CreateAsync`, `ReadAsync(id)`, `ReadAsync()` (all), `FilterAsync(pageIndex, pageSize, filters...)`,
`SearchAsync(pageIndex, pageSize, text)`, `UpdateAsync(entity)`, `DeleteAsync(id)` (returns affected rows), `CheckAsync(predicate)`.
All take a trailing `CancellationToken cancellationToken = default`.

## 5. Dependency injection and composition roots

Each project exposes one public static `DependencyInjection` class at its root. Hosts compose them:

```csharp
// Presentation.WebApi/Program.cs
builder.AddStartup();                                        // MVC + filters, IActiveUserService, OpenAPI, cache, rate limit,
                                                             // Serilog, health checks, CORS, versioning, compression, auth
builder.Services.AddApplicationLayer(builder.Configuration); // TimeProvider, handlers, Mapster, validators
builder.Services.AddDocumentsLayer(builder.Configuration);   // when the module exists
builder.Services.AddMessagingLayer(builder.Configuration);   // when the module exists
builder.Services.AddPersistenceLayer(builder.Configuration); // DataContext (SQL Server), repositories
```

**Every host is a complete composition root.** `AddApplicationLayer` registers *all* handlers, and in Development the container
validates every registration at startup (`ValidateOnBuild`) - so a host that calls `AddApplicationLayer` must also call every
Infrastructure layer whose ports any handler uses (Persistence, Documents, Messaging), even if that host never runs those use
cases. Otherwise it crashes on start with "Unable to resolve service for type ...". (The reference repo's Worker avoided this by
registering single handlers by hand - don't copy that; compose the layers.)

**Hosted services are registered apart from ports.** `Add{Layer}Layer` registers only adapters for ports; background loops are
opt-in per host: Kafka consumers via `services.AddMessagingConsumers()` (called by exactly one host, by default the WebApi),
in-process queue workers via `AddHostedService<...>()` in the host that owns the queue, cron jobs in Presentation.Worker.
Otherwise every process that composes the layer would consume the same messages.

Worker and MCP hosts register `IActiveUserService` as `SystemActiveUserService` (there is no HTTP user), then the layers.
`DataContext` depends on `IActiveUserService` and `TimeProvider`, so every host that uses Persistence must register both.

Lifetimes:
- Handlers: **transient**, listed explicitly in `AddHandlers()` under `// commands`, `// queries`, `// notifications`.
- Repositories, `DataContext`, `IDocumentService`, `IActiveUserService`: **scoped**.
- Kafka producer (`IMessagingService`), `TimeProvider`, MinIO client: **singleton**.
- In-process queues (`Channel<T>` + its `Writer`/`Reader`): **singleton, registered in `AddApplicationLayer`** (handlers that
  write to them must be constructible in every host).
- Typed HTTP clients: `AddHttpClient<IPort, Adapter>()` (transient, managed handlers).
- Kafka consumers, in-process queue workers, cron jobs: `AddHostedService<T>()` in the one host that runs them (see above).
  A hosted service is a singleton: it must create a scope (`IServiceScopeFactory.CreateScope()`) per message/run to use
  scoped services.

Validators are discovered with `AddValidatorsFromAssembly`; no manual registration.

Global usings live at the top of the layer's `DependencyInjection.cs`:
- Core.Application: `Core.Shared.Exceptions`, `FluentValidation`
- Infrastructure.Persistence: `Microsoft.EntityFrameworkCore`
- Presentation.WebApi: `Core.Shared.Exceptions`, `Core.Shared.Extensions`, `Microsoft.AspNetCore.Mvc`,
  `Microsoft.Extensions.Caching.Memory`, `Presentation.WebApi.Extensions.Attributes`, `System.Text`, and - once they exist -
  `Core.Application.DTOs`, `Core.Application.Interactors.Commands`, `Core.Application.Interactors.Queries`.

## 6. Configuration map

| Key | Used by | Notes |
|---|---|---|
| `ConnectionStrings:DefaultConnection` | Persistence, SQL health check | read with `GetString`; password in user-secrets |
| `Serilog` | WebApi | `ReadFrom.Configuration`; Seq + Graylog sinks |
| `Cors:Origins`, `Cors:ExposedHeaders` | WebApi | arrays |
| `IpRateLimiting` | WebApi | AspNetCoreRateLimit options |
| `ApiKey` | `ApiKeyAuthenticationAttribute` | secret |
| `JwtSettings:Issuer`, `:Audience`, `:Key` | JWT (optional) | key is a secret |
| `ExternalServices:<Name>` | typed HttpClient base address **and** its URL health check | one key, used by both; base address ends with `/` |
| `ApacheKafka:BootstrapServers`, `ApacheKafka:Group` | producers, consumers | |
| `MinioConfigs:MinioBucket:BucketName`, `MinioConfigs:MinioClient:{Endpoint,AccessKey,SecretKey}` | Documents | bound to `MinioSettings`; keys are secrets |
| `ServiceReferenceConfiguration:{BasicHttpBindings,EndpointConfigs}` | WCF clients | endpoint `Name` = generated client class name |
| `CronExpression` | Worker | Cronos 5-field syntax |

`appsettings.json` holds non-secret defaults; `appsettings.Development.json` local values; Production/Staging files start empty and
real values come from the environment.

Pin versions in the csproj (no floating `*`). When adding a package to an existing solution, use the version that solution
already uses for that package family. `dotnet list package --vulnerable` / `--outdated` before upgrading.

Not used, on purpose:
- **MediatR** - commercial license; handlers are called directly. **AutoMapper** - commercial license; Mapster instead.
- **FluentValidation.AspNetCore** auto-validation - replaced by `FluentValidationFilter` (and `ValidateOrThrowAsync` off-HTTP).
- **Generic `Repository<T>` / `UnitOfWork`** - deprecated by the author: they hide EF Core, grow into god-interfaces and add
  nothing in this architecture.
- **Swashbuckle document generation** (`AddSwaggerGen`) - the built-in `AddOpenApi` produces the document.
- **Localization** (`IStringLocalizer`, resx) - messages are English inline.
- **Minimal APIs** - endpoints are controllers.
